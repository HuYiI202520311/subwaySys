# 用例详细描述（作业第 1 问）

## 一、参与者与用例一览

| 参与者 | 说明 |
|---|---|
| 乘客 | 系统唯一的外部使用者，通过命令行/测试界面与系统交互 |

| 用例编号 | 用例名称 | 说明 |
|---|---|---|
| UC-01 | 查询线路与站点信息 | 某站拥有的线路数、某条线路拥有的站点数 |
| UC-02 | 查询中转站 | 识别至少两条线路经过的站点及其线路集合 |
| UC-03 | 查询附近站点 | 与给定站点线路距离小于 n 的所有站点 |
| UC-04 | 查询两点间全部无环路径 | 枚举起点到终点的所有不重复经过站点的路径 |
| UC-05 | 查询最短路径 | 返回里程最小的乘车路径（本描述所选用例） |
| UC-06 | 简洁展示乘车方案 | 按乘车段展示"乘坐/换乘某线从A到B" |
| UC-07 | 计算乘车票价 | 泛化出单程票、武汉通（9折）、定期票（0元）三种计价 |

关系：UC-05 «include» UC-06；UC-07 «include» UC-04（需先取得路径集合供用户选择）；
单程票计价、武汉通计价、定期票计价 泛化自 UC-07。

## 二、用例 UC-05 查询最短路径 的详细描述

| 项目 | 内容 |
|---|---|
| 用例名称 | 查询最短路径 |
| 用例编号 | UC-05 |
| 参与者 | 乘客（主参与者） |
| 用例描述 | 乘客输入起点站与终点站名称，系统在线网中查找总乘车里程最小的一条路径，返回从起点到终点依次经过的所有站点，以及总里程与换乘次数 |
| 前置条件 | 系统已从 subway.txt 成功加载线网数据（12 条线路、250 个车站）；输入的站点名称存在于线网中 |
| 后置条件 | 成功：返回最短路径（站点序列、乘车区间序列、总里程、换乘次数），并触发 UC-06 展示乘车方案；失败：系统状态不变，向乘客给出异常提示 |

### 基本流（主成功场景）

1. 乘客输入起点站名称与终点站名称；
2. 系统校验输入合法性：站点是否存在（兼容"××站"后缀的口语化输入）、起点与终点是否相同；
3. 系统以区间里程为边权，采用 Dijkstra 算法计算起点到终点总里程最小的路径；里程相同时优先选择换乘次数少的路径；
4. 系统从终点回溯构造路径，得到从起点开始直到终点所经过的所有站点的数组，并统计总里程（公里）与换乘次数；
5. 系统返回该最短路径，并包含执行 UC-06（简洁展示乘车方案），按乘车段打印"从A乘坐X线至B、在B换乘Y线至C"；
6. 用例结束。

### 备选流

- 3a. 存在多条总里程相同的最短路径：系统返回其中换乘次数最少的一条；
- 1a. 乘客以"中南路站"等带"站"后缀的名称输入：系统自动去掉后缀匹配到"中南路"，继续基本流。

### 异常流

- 2a. 起点或终点站点不存在：系统抛出 SubwayException，提示"站点不存在: ××"，用例结束；
- 2b. 起点与终点为同一站点：系统抛出 SubwayException，提示"起点与终点不能相同"，用例结束；
- 2c. 两站之间不存在任何可达路径：系统抛出 SubwayException，提示不存在可达路径，用例结束。

### 业务规则与补充说明

- 里程单位为公里，取 subway.txt 中相邻两站区间数据之和；
- 不同线路的同名车站视为同一换乘节点，换乘不产生额外里程；
- 本用例对应评分功能 4（20 分），实现位于 `SubwayNetwork.findShortestPath`；
- 对应的用例图与类图见同目录 `用例图.png`、`类图.png`。
